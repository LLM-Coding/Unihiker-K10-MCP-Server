== System Boundary

=== What's INSIDE the K10 MCP Server

The system consists of code running **directly on the ESP32-S3 microcontroller** inside the UNIHIKER K10 board:

* MicroPython runtime
* MCP JSON-RPC protocol handler
* HTTP server (Microdot framework)
* Hardware abstraction layer (`unihiker_k10` module)
* Tool implementations (RGB, sensors, display)

----

== External Interfaces

=== 1. MCP Client Interface (Claude Desktop)

**Type:** Inbound HTTP REST API

**Endpoint:** `POST http://<K10_IP>:8080/mcp`

**Protocol:** 
- Transport: HTTP/1.1 (no TLS due to MicroPython limitations)
- Message format: JSON-RPC 2.0
- Session management: `Mcp-Session-Id` header

**Supported MCP Methods:**
[cols="1,2,1",options="header"]
|===
|Method |Purpose |Direction

|`initialize`
|Handshake, negotiate capabilities
|Client → Server

|`tools/list`
|Discover available tools
|Client → Server

|`tools/call`
|Execute a tool (e.g., set LED, read sensor)
|Client → Server
|===

**Example Request:**
[source,json]
----
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "set_rgb_led",
    "arguments": {
      "led_num": 0,
      "r": 255,
      "g": 0,
      "b": 0
    }
  }
}
----

**Example Response:**
[source,json]
----
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "LED 0 set to RGB(255, 0, 0)"
      }
    ]
  }
}
----

=== 2. Health Check Interface

**Type:** Inbound HTTP REST API

**Endpoint:** `GET http://<K10_IP>:8080/`

**Purpose:** Verify server is running, get version info

**Response:**
[source,json]
----
{
  "server": "k10-mcp-server",
  "version": "0.3.0",
  "transport": "streamable-http",
  "status": "running",
  "mcp_version": "2024-11-05",
  "endpoint": "/mcp"
}
----

=== 3. Hardware Interface (K10 Board)

**Type:** Outbound hardware control

**Communication:** Through `unihiker_k10` Python module

**Components:**

[cols="1,2,2",options="header"]
|===
|Hardware |Purpose |Control Method

|**RGB LEDs (3x)**
|Visual feedback, status indication
|`rgb.write(num, R, G, B)`

|**Temperature/Humidity Sensor**
|Environmental monitoring
|`temp_humi.read_temp()`, `read_humi()`

|**Light Sensor**
|Ambient light detection
|`light.read()` → 0-4095

|**Accelerometer**
|Motion detection, orientation
|`acce.read_x/y/z()` → g-force

|**2.8" TFT Display**
|Text, graphics, status display
|`screen.draw_text()`, `draw_rect()`, etc.

|**Buttons (A, B)**
|User input (not yet implemented in MCP)
|`button.read('a')` → bool

|**Microphone**
|Audio input (future feature)
|`mic.start()`

|**Speaker**
|Audio output (future feature)
|`speaker.play_sound()`
|===

=== 4. WiFi Interface

**Type:** Outbound network communication

**Purpose:** Connect to local network for MCP access

**Configuration:** Set in `boot.py`

[source,python]
----
wifi.connect(ssid='NETWORK_NAME', psd='PASSWORD', timeout=50000)
----

**Status Check:**
[source,python]
----
if wifi.status():
    info = wifi.info()  # Returns: "IP, subnet, gateway, DNS"
----

== Neighbor Systems and Rationale

=== Claude Desktop

**Relationship:** Primary client

**Rationale:** 
- MCP native support (no custom client needed)
- Natural language interface to hardware
- Demonstrates AI-to-embedded integration

**Interface Design Choice:**
- HTTP instead of stdio/SSE because embedded devices lack stdin/stdout process model
- JSON-RPC for standardization and tool discoverability

=== Thonny IDE

**Relationship:** Development tool

**Rationale:**
- Popular in MicroPython community
- Simple USB serial connection
- REPL access for debugging

**Alternative Considered:** VS Code with Pymakr extension
- Rejected: More complex setup for beginners

=== Microdot Framework

**Relationship:** Embedded dependency

**Rationale:**
- Lightweight HTTP server for MicroPython (~10KB)
- Async support (needed for future WebSocket transport)
- Maintained and well-documented

**Alternative Considered:** Native socket programming
- Rejected: Too low-level, error-prone, reinventing wheel

=== unihiker_k10 Module

**Relationship:** Hardware abstraction layer

**Rationale:**
- Vendor-provided, knows hardware specifics
- Stable API, tested by manufacturer
- Saves development time vs. raw driver code

**Risk:** Proprietary, not open source
- Mitigation: Document all HAL calls in code comments
- Future: Could create open-source alternative

== Data Flow: Typical MCP Tool Call

[plantuml, dataflow, svg]
----
@startuml
actor User
participant "Claude Desktop" as Claude
participant "K10 HTTP Server" as Server
participant "MCP Handler" as MCP
participant "Tool Executor" as Tool
participant "HAL" as HAL
participant "K10 Hardware" as HW

User -> Claude: "Turn left LED red"
Claude -> Claude: Parse intent\n→ set_rgb_led(0, 255, 0, 0)
Claude -> Server: POST /mcp\nJSON-RPC request
Server -> MCP: parse_request()
MCP -> MCP: Validate method & params
MCP -> Tool: execute_tool("set_rgb_led", {...})
Tool -> HAL: rgb.write(num=0, R=255, G=0, B=0)
HAL -> HW: I2C command to LED driver
HW --> HAL: ACK
HAL --> Tool: Success
Tool --> MCP: {"content": [{"type": "text", "text": "LED 0 set..."}]}
MCP --> Server: JSON-RPC response
Server --> Claude: HTTP 200 + JSON
Claude --> User: "I've turned the left LED red"
@enduml
----

**Key Points:**

1. Claude Desktop talks to **both** Anthropic's API (for LLM) and K10 (for tools)
2. K10 only needs local network access (no internet required for MCP)
3. Router provides DHCP, K10 discovers its own IP via `wifi.info()`

== Security Boundaries

[WARNING]
====
**No Authentication/Authorization:** Current implementation has NO security.

Anyone on the network can:
- Control hardware
- Read sensor data
- Execute any tool
====

**Threat Model:**

[cols="1,2,1,1",options="header"]
|===
|Threat |Impact |Likelihood |Current Mitigation

|**Unauthorized Access**
|Attacker controls hardware
|HIGH (if on same WiFi)
|NONE - trusted network assumed

|**DoS Attack**
|Server crashes, hardware unresponsive
|MEDIUM
|NONE - no rate limiting

|**MitM Attack**
|Command interception/modification
|LOW (local network)
|NONE - no TLS (MicroPython limitation)

|**Malicious Tool Arguments**
|Hardware damage (e.g., LED overbrightness)
|LOW
|Input validation in tool executors
|===

**Future Security (v1.0+):**
- API key in HTTP header
- IP whitelist
- TLS (if MicroPython adds support)
